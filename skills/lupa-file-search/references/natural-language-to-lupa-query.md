# Natural Language → LUPA Query Conversion Guide

**Purpose**: When user asks a file search question in Korean, systematically convert it to LUPA CLI syntax.

## Conversion Rules

### Pattern 1: "X 폴더에서 Y 찾아"
```
자연어: "심사보고서 폴더에서 GCRM 파일 찾아"
분석: 
  - 폴더 = 심사보고서 → f:심사보고서
  - 파일명 = GCRM → n:gcrm
변환: f:심사보고서 n:gcrm
```

### Pattern 2: "X에서 Y 내용 찾아"
```
자연어: "심사보고서에서 경영검토 언급된 문서"
분석:
  - 폴더 = 심사보고서 → f:심사보고서
  - 내용 = 경영검토 → c:경영검토
변환: f:심사보고서 c:경영검토
```

### Pattern 3: "X 파일 중 Y 내용"
```
자연어: "GCRM 파일 중 경영검토"
분석:
  - 파일명 = GCRM → n:gcrm
  - 내용 = 경영검토 → c:경영검토
변환: n:gcrm c:경영검토
```

### Pattern 4: "최근 수정된 Y"
```
자연어: "이번 달 추가된 보고서"
분석:
  - 날짜 = 2026-08-01 이후 → 날짜:2026-08-01
  - 종류 = 보고서 = 문서 → 종류:문서
변환: 날짜:2026-08-01 종류:문서
```

### Pattern 5: "X지만 Y 제외"
```
자연어: "계약서 찾되 draft는 빼고"
분석:
  - 파일명 = 계약 → n:계약
  - 제외 = draft → -draft
변환: n:계약 -draft
```

## 실행 워크플로우

1. **사용자 요청 파싱**
   - 자연어 쿼리 읽기
   - 위의 패턴 중 어느 것에 맞는지 판단

2. **LUPA 쿼리 조립**
   - 각 조건을 `f:`, `n:`, `c:`, 등으로 변환
   - 공백으로 구분해 AND 연결

3. **CLI 실행**
   ```bash
   /Volumes/WD_NVMe_1T/DEV/Lupa/cli/lupa-search "변환된_쿼리"
   ```

4. **결과 정렬 및 제시**
   - JSON 파싱
   - `matched_keywords` 높은 순서대로 정렬
   - 상위 3-5개 추천

## 주의사항

- **한글 정규화**: 자모 분리 문제는 LUPA가 내부에서 처리 (NFC/NFD 정규화)
- **조사 자동 처리**: "에서", "중에", "의" 같은 조사는 무시하고 주요 명사만 추출
- **AND 기본**: 공백 구분 조건은 모두 AND. OR이 필요하면 별도 문의
- **정확 구문**: 예) `"ISO 27001"` (공백 포함) vs `ISO 27001` (각각 검색)

## 자연어 신호 → 추천 옵션

| 신호 | 적용 |
|------|------|
| "폴더" 언급 | `f:폴더명` 필수 |
| "내용", "언급", "포함" | `c:키워드` 필수 |
| "최근", "이번 달", "2026년" | `날짜:` 필터 추가 |
| "-" "빼고", "제외" | `-키워드` 추가 |
| "정확히" "딱" | `"정확구문"` 사용 |
